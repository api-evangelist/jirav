## What an agent needs to know first

Jirav has **no public API**. There is no developer portal, no API reference, no OpenAPI /
AsyncAPI / GraphQL / SOAP contract, no SDK in any package registry, no CLI, no webhooks, no
MCP server, and no A2A agent card. Every "integration" Jirav markets is an inbound, one-way
connector that Jirav operates *against another vendor's* API to pull the customer's actuals in.
Nothing can be programmatically read out of, or written into, Jirav by a third party.

An agent asked to "call the Jirav API" should stop here and say so.

## Product

- Reporting, dashboards and KPIs over imported financial actuals
- Planning, budgeting and rolling forecasts, including three-way pro forma financials
  (income statement, balance sheet, cash flow)
- Workforce/staffing planning and driver-based models
- Scenario comparison and auto-forecast
- White-labeled report packages for accounting and CFO advisory firms

## Integrations (inbound connectors Jirav operates, not APIs Jirav exposes)

- Accounting/GL: QuickBooks Online, QuickBooks Desktop, Xero, Oracle NetSuite, Sage Intacct
- Payroll/HR: Gusto, Paychex Flex, ADP RUN, BambooHR, Paylocity, TriNet, Justworks, UKG Ready
- Files: Excel and Google Sheets uploads, custom line and custom table imports
- SSO/sign-in: Google, Microsoft, Xero
- Constraints Jirav publishes: one accounting system per account, single currency, one-way
  import only (Jirav never writes back), and the accounting connection cannot be changed by
  the customer without a support ticket
  — https://help.jirav.com/actuals/integration-capabilities
